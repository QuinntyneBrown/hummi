Theming

Light is the default; dark follows the device or an explicit choice. Both are built from the same roles.

Overview

Tokens come in three tiers: primitives (raw values), semantic (meaning; themes override this tier) and component tokens (scoped aliases). Changing a hue touches primitives; changing what “accent” means touches semantic tokens.

How themes apply

  • Light is :root.
  • Dark applies with [data-theme="dark"] and, unless the page forces light, with prefers-color-scheme: dark.
  • color-scheme is set per theme so native controls and scrollbars follow.
  • prefers-contrast: more and forced-colors raise borders and hand focus and borders to system colours.

Adding a theme

  1. Copy the [data-theme="dark"] block in tokens/tokens.css and rename it.
  2. Override semantic tokens only.
  3. Add the new pairs to tokens/contrast-pairs.json and run check_contrast.py.
  4. Re-export with tokens_to_json.py.

Consuming tokens.json

tokens/tokens.json is a DTCG export ($type, $value, aliases as {group.token}, theme overrides under $extensions). Generate platform constants from it; do not hand-copy values.

Do and don’t

  • Do change semantic tokens to re-theme.
  • Don’t write a colour literal in a component.
  • Don’t invert light values to make dark.
