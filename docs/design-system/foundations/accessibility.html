Accessibility

Hummi commits to WCAG 2.2 AA: contrast, keyboard, focus, labels, targets and motion.

WCAG 2.2 AAStatus: stable
  • Overview
  • Commitments
  • Global keyboard map
  • Testing procedure
  • Component contract
  • Interaction tokens

Overview

Accessibility is part of the component contract, not a final check. Each component page documents its role, keyboard map, focus, labelling, contrast, motion and touch behaviour.

Commitments

  • Text contrast 4.5:1 (3:1 for large text); UI edges and focus rings 3:1.
  • Everything works with a keyboard; focus is always visible (:focus-visible ring, 2px, offset 2px).
  • Every control has a name; icon-only controls have aria-label.
  • Targets are at least 24px, and 44px for primary touch controls.
  • Colour is never the only cue.
  • One h1 per page; landmarks and a skip link on every page.
  • Dialogs trap focus, make the page inert and return focus; toasts live in a polite live region.
  • Motion respects prefers-reduced-motion; nothing flashes.

Global keyboard map

KeyAction
Tab / Shift+TabMove between controls
SpacePlay or pause (outside text fields)
EscClose dialog, menu or toast
/Focus search

Testing procedure

  1. Tab through the page; the order matches reading order and the ring is always visible.
  2. Run the contrast check on both themes.
  3. Zoom to 200% and 400%: no loss of content.
  4. Use a screen reader on one page, one dialog and one toast.

Component contract

A component is done when its page names the ARIA pattern, lists the keys, shows focus and both themes, and its contrast pairs are in contrast-pairs.json.
