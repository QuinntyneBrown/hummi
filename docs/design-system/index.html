Components

  • Button

    Buttons trigger an action on the current page. Five variants, three sizes, every state.

  • Button group

    Joins related buttons into one segmented control or toolbar.

  • Link

    Links navigate. They are underlined so colour is never the only cue.

  • Menu

    A short list of actions opened from a button, such as a track’s More menu.

  • Text field

    A single-line input with a visible label, optional help and an inline error.

  • Textarea

    A multi-line input for notes and descriptions.

  • Select

    A native dropdown for choosing one option from a fixed list.

  • Checkbox

    Lets people turn one or more independent options on or off.

  • Radio group

    Chooses exactly one of a few visible options.

  • Switch

    Turns a setting on or off immediately.

  • Form field

    The wrapper every input uses: label, control, help, error and counter in a fixed order.

  • Form layout

    How fields, the error summary and the actions bar sit together on a page.

  • Top bar

    The sticky header: navigation menu on small screens, search, notifications and account.

  • Sidebar navigation

    The permanent primary navigation on wide screens and a slide-in on small ones.

  • Tabs

    Switch between related views of the same content without leaving the page.

  • Breadcrumb

    Shows where a page sits in the hierarchy and links back up.

  • Pagination

    Moves through long result sets one page at a time.

  • Skip link

    The first focusable element on every page; jumps keyboard users past the navigation.

  • Card

    A bordered surface that groups related content.

  • Dialog

    A modal that asks for a decision or a short form; a bottom sheet on phones.

  • Tooltip

    A short label that appears on hover and focus.

  • Divider

    A thin rule that separates groups.

  • Layout primitives

    Container, grid, stack and cluster: the building blocks every page template uses.

  • Table

    Compares records across columns. Scrolls inside its own wrapper on small screens.

  • List

    A vertical list of rows with a title, meta line and optional actions.

  • Description list

    Key and value pairs for facts about one thing.

  • Avatar

    A circle with initials identifying a person.

  • Badge

    A small label showing status or a count.

  • Chip

    A compact toggle or link, used for filters and genres.

  • Toast

    A transient message about something that just happened.

  • Alert and banner

    Inline messages and page-wide banners in four tones.

  • Inline message

    Hint, error and success text attached to a field or control.

  • Progress bar

    Shows how far a known task has got, or that one is running.

  • Spinner

    A small rotating ring for short, unknown waits inside a control.

  • Skeleton

    Placeholder blocks that match the final layout while content loads.

  • Empty state

    Explains why a place is empty and offers the one next step.

  • Error page

    Full-page 404, 403, 500 and offline states that keep the app shell.

  • Cover

    Generated artwork tile for a track, album or playlist.

  • Track row

    One track in a list: number, cover, title, artist, duration and actions.

  • Media tile

    A clickable tile for a track, artist or playlist in a grid shelf.

  • Genre tile

    A bold coloured tile that links to a genre.

  • Player bar

    The persistent mini player fixed to the bottom of every page.

  • Waveform

    A visual summary of a track’s loudness with the played portion highlighted.

  • Hero

    A featured block at the top of a page: cover, kicker, title, text and actions.

  • Notification item

    One entry in the notification centre, unread or read.

  • Search layer

    The header search pill and the layer that drops in over the page: query bar, top result, result rows, recent searches and sound tiles.

How to use

  1. Link tokens/tokens.css then assets/components.css.
  2. Use the documented classes and data-theme for dark mode; never write colours or sizes in a feature.
  3. Generate platform constants from tokens/tokens.json.
  4. In Angular, @hummi/components wraps these classes; if something is missing, add it here first.
