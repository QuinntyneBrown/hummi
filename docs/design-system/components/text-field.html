Text field

A single-line input with a visible label, optional help and an inline error.

WCAG 2.2 AAStatus: stable

Overview

Use a text field for short free text: names, emails, passwords, search. Use a textarea for more than one line and a select for a fixed list.

Anatomy

  1. LabelAlways visible, above the input
  2. Input40px tall, strong border, --radius-md
  3. Help textOptional, linked with aria-describedby
  4. ErrorReplaces help; icon and text, never colour alone

Responsive behaviour

Fields are full width of their column. Two-column forms collapse to one column under 768px. Font size is never below 16px on touch so iOS does not zoom.

Theming

Component tokens alias semantic tokens only; re-theme by overriding the semantic tokens, never the component CSS.

Accessibility

Role and pattern

Native <input> with a <label for>.

Keyboard

KeyAction
TabMoves to the field
EscClears a search field

Focus

Border turns accent and the standard focus ring shows.

Labelling

Every field has a label; placeholders are examples, never labels. Errors and help are connected with aria-describedby; invalid fields set aria-invalid="true".

Contrast

Input border
Placeholder
Error text

Motion

No motion beyond colour transitions, which collapse to zero under prefers-reduced-motion.

Touch

Targets are at least 24px and 44px on touch-primary controls.

Content

Labels are nouns in sentence case (“Display name”). Errors say what is wrong and how to fix it: “Use at least 10 characters”.
