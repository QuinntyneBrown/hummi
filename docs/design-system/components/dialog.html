Dialog

A modal that asks for a decision or a short form; a bottom sheet on phones.

WCAG 2.2 AAStatus: stable

Overview

Use for a decision or a task that needs full attention and is quick. For long tasks use a page. Destructive dialogs name the object and use a danger button.

Anatomy

  1. BackdropDims and blocks the page, which is inert
  2. HeaderIcon, title (h2), description, close button
  3. BodyFields or content
  4. FooterCancel then primary

Variants

In the product the panel is centred in a fixed .dialog over a .backdrop; here it is shown in flow.

Responsive behaviour

Accessibility

Role and pattern

WAI-ARIA Dialog (modal): role="dialog" aria-modal="true" with aria-labelledby and aria-describedby. The page behind is inert.

Keyboard

KeyAction
Tab / Shift+TabCycles inside the dialog
EscCloses (unless a request is running)
EnterActivates the focused button

Focus

Focus starts on the first field or the safe button and returns to the trigger on close.

Labelling

Title names the dialog; description explains the consequence.

Contrast

Text
Muted text

Motion

Slides up in --duration-slow; fade only under reduced-motion.

Touch

Targets are at least 24px and 44px on touch-primary controls.

Content

Title is a question or a verb phrase that names the object. Buttons repeat the verb: “Delete playlist”, not “OK”.
