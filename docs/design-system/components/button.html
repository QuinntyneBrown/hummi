Button

Buttons trigger an action on the current page. Five variants, three sizes, every state.

WCAG 2.2 AAStatus: stable

Overview

Use a button for something that does something: play, save, create, delete. Use a link to go somewhere. Each view has at most one primary button; everything else is secondary or ghost.

Anatomy

  1. Leading icon (optional)20px, inherits the label colour
  2. LabelVerb phrase in sentence case
  3. Container40px tall, --radius-md, 16px inline padding

Variants

The accent marks the single most important action. Danger is reserved for destructive actions and always follows a confirmation.

Responsive behaviour

Buttons keep their height at every width. Under 640px primary actions in forms and dialogs become btn--block; toolbars wrap onto a second line with .cluster instead of shrinking labels. Labels never truncate.

Theming

Primary reads --color-accent with --color-fg-on-accent: coral with white text in light, bright coral with plum text in dark. Component tokens alias semantic tokens only; re-theme by overriding the semantic tokens, never the component CSS.

Accessibility

Role and pattern

Native <button type="button">. Toggles use aria-pressed; disclosure buttons use aria-expanded.

Keyboard

KeyAction
Enter / SpaceActivates the button
TabMoves to the next control

Focus

A 2px ring in --color-focus-ring, offset 2px, appears on :focus-visible. Busy buttons stay focusable so focus is not lost.

Labelling

Visible text is the name. Icon-only buttons need aria-label naming the action and its object (“Like Slow Orbit”).

Contrast

Label on primary
Label on danger
Label on secondary

Motion

Hover and press colour changes last --duration-fast.

Touch

Icon-only and mobile primary buttons are 44px; small buttons are used only in dense desktop rows.

Content

  • Verb first, sentence case: Add to playlist, not Playlist or ADD.
  • Name the object when several buttons share a view: Delete playlist.
  • While busy, switch to the gerund: Saving….
