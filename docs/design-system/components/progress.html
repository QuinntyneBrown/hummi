Progress bar

Shows how far a known task has got, or that one is running.

WCAG 2.2 AAStatus: stable
  • Overview
  • Anatomy
  • Variants
  • Sizes

Overview

Use determinate bars when you know the fraction (track position, upload). Use indeterminate when you do not.

Anatomy

  1. TrackRounded rail
  2. BarFill in accent

Variants

Determinate
HTML
<div class="progress" role="progressbar" aria-label="Track position" aria-valuemin="0" aria-valuemax="252" aria-valuenow="84"><div class="progress__bar" style="width:33%"></div></div>
Indeterminate
HTML
<div class="progress progress--indeterminate" role="progressbar" aria-label="Confirming email"><div class="progress__bar"></div></div>
Success
HTML
<div class="progress progress--success" role="progressbar" aria-label="Upload" aria-valuemin="0" aria-valuemax="100" aria-valuenow="100"><div class="progress__bar" style="width:100%"></div></div>

Sizes

Not applicable: Height is fixed at 8px.

States

Responsive behaviour

Full width of its container.

Theming

Component tokens alias semantic tokens only; re-theme by overriding the semantic tokens, never the component CSS.

Accessibility

Role and pattern

role="progressbar" with aria-valuenow, min, max; indeterminate omits value.

Keyboard

KeyAction
n/aNot interactive

Focus

Not focusable; the scrubber in the player is a slider, documented with Player bar.

Labelling

Name says what is progressing.

Contrast

Bar vs track

Motion

Indeterminate loops in --duration-deliberate; static under reduced-motion.

Touch

Targets are at least 24px and 44px on touch-primary controls.

Content

Show remaining time or percent only when reliable.
