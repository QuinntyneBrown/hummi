Tabs

Switch between related views of the same content without leaving the page.

WCAG 2.2 AAStatus: stable

Overview

Use tabs for peers such as Playlists, Liked and Following. If each view has its own URL and heavy content, use sub-pages instead.

Anatomy

  1. Tab listUnderlined row, scrolls on small screens
  2. Tab44px tall; selected has an accent underline
  3. Count (optional)Badge inside the tab

Variants

Underline with count
HTML
<div class="tabs" role="tablist" aria-label="Library"><button class="tab" role="tab" aria-selected="true" type="button">Playlists</button><button class="tab" role="tab" aria-selected="false" tabindex="-1" type="button">Liked <span class="badge">41</span></button><button class="tab" role="tab" aria-selected="false" tabindex="-1" type="button">Following</button></div>

Sizes

Not applicable: Tabs are 44px tall.

States

VariantDefaultHoverFocusSelectedDisabled
Tab

Both themes

Responsive behaviour

The tab list scrolls horizontally when it overflows; no wrapping, no truncation.

Theming

Component tokens alias semantic tokens only; re-theme by overriding the semantic tokens, never the component CSS.

Accessibility

Role and pattern

WAI-ARIA Tabs: tablist, tab, tabpanel. Activation is automatic on arrow keys.

Keyboard

KeyAction
← →Moves to and activates the previous or next tab
Home / EndFirst or last tab
TabMoves into the panel from the selected tab

Focus

Only the selected tab is in the tab order (tabindex="-1" on the rest).

Labelling

List has aria-label; each panel is labelled by its tab.

Contrast

Selected
Unselected

Motion

No motion beyond colour transitions, which collapse to zero under prefers-reduced-motion.

Touch

Targets are at least 24px and 44px on touch-primary controls.

Content

One-word labels in sentence case; counts only when they help decisions.
