Search layer

The header search pill and the layer that drops in over the page: query bar, top result, result rows, recent searches and sound tiles.

WCAG 2.2 AAStatus: stable

Overview

Search is a layer, not a page (ADR 0004). The pill in the header opens it; the bar keeps the query; results group into a Top result card, Artists and Songs rows. With an empty query it lists recent searches and Browse by sound tiles.

Anatomy

  1. Search pillsearch-pill in the header end slot with the / key hint
  2. Barlayer-search__bar: icon, input, Clear (only with text), Close
  3. Top resulttop-result: cover, title, “artist · duration”
  4. Result rowsrow (songs) and srow--artist
  5. Recentrecent list with clock icons
  6. Sound tilesound genre tile with title and “{n} tracks”

Sizes

Not applicable: The layer spans the viewport width; rows and tiles fill their column.

States

Responsive behaviour

Under 64rem results stack in one column; from 64rem the top result sits beside the lists and the empty state puts Recent beside Browse by sound. The pill shows from 48rem; below it an icon button opens search.

Theming

Component tokens alias semantic tokens only; re-theme by overriding the semantic tokens, never the component CSS.

Accessibility

Role and pattern

The layer is role="dialog" with aria-modal and the label “Search”; the playing row has aria-current="true".

Keyboard

KeyAction
/Opens search when no text field is focused
EscapeCloses the layer
EnterSearches at once

Focus

The query field takes focus on open; focus returns to the pill on close.

Labelling

The input and pill are labelled “Search songs and artists”; More buttons name the track.

Row title

Motion

The layer drops in over 200 ms; reduced motion removes the animation.

Touch

Targets are at least 24px and 44px on touch-primary controls.

Content

No results: “Nothing matches “{query}”” with “Try an artist name, or a sound like soca, pan or lullaby.” Errors keep the query in the bar.
