Pattern

Forms

Layout, validation timing, error summary and submit states.

WCAG 2.2 AAStatus: stable

  • Responsive behaviour

Overview

Forms collect input with as little friction as possible. One column, visible labels, validation that helps rather than scolds.

When to use what

  • Use a page form for account and settings; a dialog form for one to three fields.
  • Validate on blur, then on input once a field has been touched. Never clear typed values.
  • Destructive confirmations use a typed name only when the loss is large.

States

Submitting: the primary button shows a spinner and aria-busy, fields turn read-only, width does not change. Failed: the summary appears at the top and takes focus. Success: say what happened and where to go next.

Responsive behaviour

Single column at every width. Two-column layouts collapse under 768px. Primary buttons go full width under 640px.

Accessibility

  • Every control has a label; errors use aria-describedby and aria-invalid.
  • The summary is role="alert" with links to fields.

Content

Labels are nouns; errors say how to fix; button verbs name the result.
