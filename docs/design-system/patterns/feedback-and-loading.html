Feedback and loading

Which feedback for which action, and skeleton vs spinner vs progress.

Overview

Match the feedback to the scope and urgency of what happened.

When to use what

SituationUse
A field is wrongInline message
An action just completedToast (with Undo if reversible)
A section’s state changedInline alert
The whole page is affectedBanner
A decision is neededDialog
Content is loadingSkeleton
A button is workingSpinner inside the button
A task has a known fractionProgress bar

States

Loading: skeletons that match the final layout. Busy: control disabled with a spinner, no layout shift. Optimistic: show the result at once and offer Undo; roll back with an error toast if it fails.

Responsive behaviour

Toasts go full width on phones. Banners wrap. Skeletons use the same grid as content.

Accessibility

  • Toast region is a polite live region; errors use role="alert".
  • Skeleton containers are aria-busy.
  • Feedback never steals focus.

Content

Say what happened in the past tense. Offer one way forward.
